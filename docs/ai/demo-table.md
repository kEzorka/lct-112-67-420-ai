# Таблица демонстрации C-10: живое / записанное / заранее подготовленное

Требование C-10 (`docs/architecture/decision-register.md`): «Таблица демонстрации указывает,
какие фрагменты живые, записанные и заранее подготовленные»; «Публичный стенд, запись видео и
заранее подготовленные ответы не служат доказательством выполнения локальных SLA, живого
inference, аппаратной телефонии или отказоустойчивости [под нагрузкой]».

Ниже — не сценарий конкретного показа, а честная классификация того, что технически может
идти вживую на этом коде сейчас, а что нужно показывать записью или заготовкой, по фактам из
существующих тестов и замеров (`test-matrix.md`, `perf-report.md`, `calibration-report.md`), без
новых прогонов.

| Фрагмент демо | Статус | Почему |
|---|---|---|
| Уведомление → открытие карточки → решение диспетчера → сдача (текстовый режим) | **Живое** | Детерминированный мок-цикл, ни одна модель не нужна; `test_cycle.py::test_text_cycle_runs_without_models`, доли секунды на попытку |
| Разговор с руководителем на фейковой LLM (`echo`/сценарный fallback) | **Живое** | Детерминировано, без сети; тот же путь, что офлайн-прогон (`test_offline_cycle.py`) |
| Разговор с руководителем на настоящей LLM (Qwen2.5-1.5B Q4, реплика по схеме `{"action","text"}`) | **Заранее подготовленное/запись** | Задержка одного вызова на этой модели по близкой свободной задаче — медиана ~5 с, p95 ~7,5 с (`bench/llm-cpu.md`, §M5); сама схема реплики руководителя на настоящей модели **не прогонялась** сквозным тестом — риск неровного ответа вживую слишком велик без предварительной проверки конкретной реплики |
| STT настоящей моделью (`faster-whisper`/`vosk`) на голосе ведущего | **Запись** | Задержка до финального результата 0,85–7,75 с на синтетическом датасете и не целевом CPU (`bench/voice-cpu.md`, §3); на живом голосе (не синтетическом) WER не измерен вообще — риск неверного распознавания в реальном времени слишком велик для живого показа |
| TTS настоящим движком (Piper/Silero) — воспроизведение одной заранее известной фразы | **Живое** | RTF < 1 у обоих движков даже на не целевом CPU (`bench/voice-cpu.md`, §4: ~0,05–0,21), задержка до полного буфера ~0,2–0,7 с — достаточно быстро для короткой заранее выбранной фразы |
| Семантическая оценка одного заранее подготовленного ответа с объяснением | **Живое, с оговоркой** | Технически отрабатывает за один вызов (медиана 5,1 с, `bench/llm-cpu.md`); согласие с рабочей меткой на контрольной выборке — 59,3% (`calibration-report.md`) — показывать нужно с явной оговоркой о качестве, не как готовое решение |
| Отказ компонента (STT/LLM/TTS/оцениватель/рекомендатель) и деградация без падения попытки | **Живое** | Ровно то, что проверяет `test_c04_matrix.py` — включение `FaultInjector` и повтор попытки занимает секунды, воспроизводимо на месте |
| Отключение сети и продолжение полного цикла офлайн | **Живое** | `test_offline_cycle.py` — реально блокирует `socket` в подпроцессе; можно буквально выключить сеть машины и повторить тот же цикл на месте |
| Отчёт преподавателю (уровень по сегменту от 3 попыток, «недостаточно данных» иначе) | **Живое** | Детерминированный расчёт (`ai/src/dds_ai/profile/build.py`), не требует моделей |
| Рекомендация следующего задания с аудитом выбора (C-08) | **Живое** | Детерминированное правило по умолчанию; воспроизводимость по сохранённым входам проверена тестом |
| Полная параллельная нагрузка (≥20 сессий) | **Не показывается** | Не замерялось никем на этом узле (см. `perf-report.md`, «Явно непроверенное») — в демо не заявляется и не имитируется |

## Что демо не доказывает (C-10, дословно применимо к этому контуру)

- **Локальные SLA производительности** (UI ≤2 с, ≥20 сессий, голос ≤150 мс) — ни один
  фрагмент выше, живой или нет, не подтверждает эти цифры; см. `perf-report.md`.
- **Живой inference на целевом железе заказчика** — все замеры и любой живой показ идут на
  окружении сборки агента (4 ядра), не на профиле `cpu` (≥6 ядер/32 ГБ, D-051).
- **Аппаратная телефония** — голосовой канал в этом контуре везде мок медиатракта
  (`MockMediaTransport`) или локальные адаптеры STT/TTS; настоящей телефонной линии в проекте
  нет и демо её не имитирует как реальную.
- **Отказоустойчивость под нагрузкой** — демонстрация отказа одного компонента на одной
  попытке (строка «Отказ компонента» выше) показывает *корректность* деградации, не
  устойчивость системы под реальной параллельной нагрузкой.
- **Готовность модели/промпта к пилоту** — семантический оцениватель и LLM-формулировка
  показываются с прямой оговоркой о качестве (59,3% согласия, `calibration-report.md`); демо
  не является приёмкой качества.
- **Запись/заготовка не заменяет живую попытку.** Записанные фрагменты (настоящие STT/LLM)
  показывают, что путь технически работает на одном заранее выбранном примере — не то, что он
  устойчиво работает на произвольном вводе вживую.
