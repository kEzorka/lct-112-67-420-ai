# Замер стадий LLM-формулировки на CPU — M3

Дата: 28.09.2026. **Это не целевое железо заказчика** (раздел 9 промпта). Замер сделан в окружении
сборки агента, а не на сервере профиля `cpu` (≥6 ядер, 32 ГБ RAM, D-051). Ни одна модель этим
отчётом не выбирается (раздел 11).

## Главное

**Замера настоящей LLM нет.** Веса GGUF-кандидатов раздаются с huggingface.co. Этот хост закрыт
сетевой политикой контейнера: 28.09.2026 `curl https://huggingface.co/api/models/...` вернул
`CONNECT tunnel failed, response 403`, как и на M2 ([`voice-cpu.md`](voice-cpu.md)). Обходить
ограничение не стали.

Что сделано вместо замера:
1. Обвязка замера по стадиям (`ai/bench/run_llm_bench.py`) проверена на детерминированном фейке.
2. Путь через настоящий runtime llama.cpp проверен дымовым прогоном. Модель для него —
   крошечная GGUF со **случайными весами**, собранная локально (`ai/bench/make_tiny_gguf.py`).
   Она проверяет адаптер, грамматику JSON, срок генерации и валидатор на живом runtime. Задержку
   или качество настоящей модели такой прогон не показывает.

## Условия

| Параметр | Значение |
|---|---|
| Платформа | `Linux-6.18.44-fc-v42-x86_64-with-glibc2.39`, 4 логических CPU (`os.cpu_count()`), контейнер |
| Python | 3.11.15 |
| Runtime | `llama-cpp-python` 0.3.35, собран из исходников pip, CPU-бэкенд |
| Промпт | `supervisor-phrase-ru-m3-1` (`ai/config/supervisor.prompt.ru.json`), `max_tokens` 160 |
| Сценарии | три синтетических (`ai/data/synthetic/`), скрипт реплик — `SCRIPTS` в `run_llm_bench.py` |
| Конкурентность | 1 (один разговор за раз) |
| Воркер | профиль `cpu` (`ai/config/worker.cpu.json`), полоса `interactive`, тайм-аут 8 с |

## Стадии

- **generation** — один вызов `LLMProvider.complete()`.
- **validation** — разбор и проверка выхода одной попытки (`supervisor/validator.py`).
- **phrase_total** — от начала формулировки до готового текста или отказа. Сюда входят очередь
  воркера, все попытки и повтор после невалидного выхода.
- **turn_total** — весь ход руководителя `Conversation.hear()`: автомат, шаблон, формулировка,
  fallback.

Первый звук TTS и транспорт аудио сюда не входят. Цель «первый звук ≤ 3 с» (D-052) этим отчётом
не проверяется. Требование ТЗ ≤ 150 мс относится к передаче голоса, а не к ответу модели.

## Результаты

### 1. Фейк `echo` без задержки: стоимость обвязки

`python run_llm_bench.py --runs 20`. 20 прогонов × 3 сценария, 220 реплик руководителя.

| Стадия | n | p50, мс | p95, мс | max, мс |
|---|---|---|---|---|
| generation | 220 | 0,01 | 0,04 | 0,08 |
| validation | 220 | 0,08 | 0,22 | 0,32 |
| phrase_total | 220 | 0,20 | 0,42 | 0,62 |
| turn_total | 180 | 0,34 | 0,66 | 0,78 |

Все 220 реплик приняты валидатором, доля fallback — 0. Фейк возвращает черновик без изменений.
Значит, на синтетических сценариях валидатор не отклоняет верную формулировку. Это же проверяет
тест `test_faithful_phrasing_is_accepted_in_every_synthetic_scenario`.

### 2. Фейк `echo` с задержкой 50 мс: стадии складываются

`python run_llm_bench.py --runs 5 --fake-latency-ms 50`, 55 реплик.

| Стадия | p50, мс | p95, мс | max, мс |
|---|---|---|---|
| generation | 50,28 | 50,36 | 50,39 |
| validation | 0,16 | 0,30 | 0,40 |
| phrase_total | 50,80 | 50,98 | 51,15 |
| turn_total | 51,10 | 51,42 | 51,44 |

Накладные расходы воркера, валидатора и автомата — меньше 1 мс на ход. Бюджет задержки
определяет генерация.

### 3. Настоящий llama.cpp, крошечная модель со случайными весами (дымовой прогон)

Модель: архитектура `llama`, 2 слоя, `n_embd` 64, байтовый словарь из 260 токенов, веса f32,
файл 470 КБ, `n_ctx` 8192. Команда:
`run_llm_bench.py --provider llamacpp --model tiny.gguf --n-ctx 8192 --runs 5`, 55 реплик,
110 попыток.

| Стадия | n | p50, мс | p95, мс | max, мс |
|---|---|---|---|---|
| generation | 110 | 298,58 | 370,37 | 414,35 |
| validation | 110 | 0,08 | 0,10 | 0,13 |
| phrase_total | 55 | 607,89 | 688,27 | 730,35 |
| turn_total | 45 | 613,32 | 699,29 | 730,61 |

Исходы попыток: `invalid_output:not_json` — 110 из 110, доля fallback — 1,0. Модель случайная.
Грамматика держит форму `{ "action": "...` на каждом токене, но строка обрывается на
`max_tokens`. Валидатор отклоняет выход, делается один повтор, затем берётся шаблонная реплика.
Поэтому `phrase_total` ≈ 2 × generation. Так будет выглядеть и настоящая модель, которая
систематически не проходит проверку. Доля fallback и исходы попыток — обязательные поля отчёта
о настоящем замере.

Что подтвердил прогон на настоящем runtime:
- адаптер загружает только локальный файл, `model_version` — отпечаток файла
  (`size469824-sha256p-…`);
- грамматика JSON-схемы работает в `create_chat_completion` и `create_completion`;
- срок генерации (`timeout_s` = 0,001 с) останавливает генерацию примерно через 45 мс,
  и адаптер бросает `TimeoutError`;
- невалидный выход доходит до валидатора, повтор и fallback срабатывают.

Два дефекта, найденные только на настоящем runtime (оба исправлены, на оба есть тесты):
1. **Аварийное завершение процесса.** Первая версия срока генерации оставляла модели только
   токен конца через обработчик логитов. Вместе с грамматикой JSON llama.cpp завершал весь
   процесс: `std::runtime_error: Unexpected empty grammar stack after accepting piece: <unk>`.
   Теперь срок генерации соблюдается чтением потока токенов: адаптер перестаёт читать поток и
   закрывает его.
2. **Неверный вид сбоя.** Промпт длиннее окна контекста даёт в llama.cpp `ValueError`, а
   `FaultInjector` записывал его как `invalid_output`. Теперь сбой runtime записывается как
   `error`, без повтора. `invalid_output` остаётся только за проверенным выходом модели.

## Что не проверено и почему

- **Задержка и качество настоящей LLM на CPU.** Веса недоступны: huggingface.co отвечает 403.
- **Доля отклонений валидатора на настоящей модели.** От неё зависит, как часто будет fallback.
  Пока ложные отказы проверены только на верной формулировке (фейк). Настоящая модель будет
  перефразировать, и часть проверок может оказаться строгой, например адресные слова или имена
  с заглавной буквы.
- **Обработка промпта до первого токена.** На длинном промпте её нельзя прервать сроком
  генерации. Этот отрезок ограничен только длиной промпта (история — 6 реплик, реплика —
  до 400 символов) и тайм-аутом воркера.
- **Конкурентность больше 1 и профиль `gpu`.** Не замерялись.
- **Первый звук TTS и итоговая задержка до слышимого ответа.** Нужны настоящие LLM и TTS
  (см. M2).

## Кандидаты для замера (не решение)

Если веса будут доступны, прогнать на целевом CPU 2–3 инструктивные модели 0,5–4 млрд
параметров с поддержкой русского языка, в квантизации Q4_K_M и Q8_0. Команда:
`run_llm_bench.py --provider llamacpp --model <файл> --model-version <из манифеста> --n-threads <ядра>`.
В отчёт внести: p50/p95/max стадий, долю fallback, исходы попыток, квантизацию и лицензию файла
весов ([`licenses.md`](../licenses.md), раздел «LLM runtime»). Модель выбирается по замеру и
лицензии, а не по этому списку.
