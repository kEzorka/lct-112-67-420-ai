## 3. STT: WER/CER общий и по сущностям, задержка, память

Датасет — 10 синтетических реплик `ai/bench/dataset.py` (адреса, номера, отрицания,
службы). Аудио синтезировано TTS-кандидатами (см. раздел 4 об этом смещении) — **не**
живой голос. Каждый STT-кандидат прогонялся в отдельном процессе (`--candidates <one>`),
чтобы `peak_rss_mb` отражал память именно этой модели, а не накопленный пик процесса,
где до неё уже отработал другой кандидат.

сохраняется на обоих наборах. `vosk-small` — заметно быстрее (0.84 с против 3-8 с) и легче
по памяти (262 МБ против 882-2141 МБ), но кратно хуже по WER/CER — компромисс размера
модели (45 МБ) против качества, не готовое решение.

## 4. TTS: время до полного буфера, RTF, память; D-025

Каждый TTS-кандидат — тоже в отдельном процессе. `avg_time_to_full_audio_s`/`avg_rtf` —
среднее по всем 10 репликам датасета, отдельно для интонаций `neutral`/`tense`.

| Кандидат/интонация | Частота, Гц | Время до буфера, с | RTF | Пиковая RSS, МБ |
|---|---|---|---|---|
| `piper-irina/neutral` | 22050 | 0.229 | 0.053 | 353 |
| `piper-irina/tense` | 22050 | 0.199 | 0.049 | 365 |
| `piper-denis/neutral` | 22050 | 0.195 | 0.053 | 332 |
| `piper-denis/tense` | 22050 | 0.190 | 0.056 | 332 |
| `silero-baya/neutral` | 48000 | 0.647 | 0.177 | 1184 |
| `silero-baya/tense` | 48000 | 0.176 | 0.058 | 1208 |
| `silero-aidar/neutral` | 48000 | 0.736 | 0.209 | 1191 |
| `silero-aidar/tense` | 48000 | 0.174 | 0.057 | 1219 |

**D-025 (мужской+женский голос, минимум 2 различимые интонации хотя бы у одного движка):**
выполнено обоими движками отдельно.
- Piper: `irina` (женский) + `denis` (мужской); интонация — `length_scale`/`noise_scale`/
  `noise_w_scale` (`neutral` vs `tense`), различие в длительности синтеза видно по времени
  (0.229→0.199 с и 0.195→0.190 с — темп меняется, не только громкость).
- Silero: `baya` (женский) + `aidar` (мужской); интонация — SSML `<prosody rate=...
  pitch=...>` (`v4_ru` поддерживает `rate`/`pitch`/`break` — см. `model.valid_tags`), а не
  только темп: `neutral` даёт длительность аудио заметно больше, чем `tense`
  (RTF 0.177→0.058 и 0.209→0.057 — не только более быстрый прогон, сам аудио-буфер короче,
  то есть темп речи реально изменился, плюс тон по `pitch`).
- Не проверено на слух качество/естественность интонации: этот прогон автоматический
  (агент, не человек), различие интонаций подтверждено только числовым
  сигналом (длительность/RTF меняется предсказуемо между `neutral`/`tense`), не
  прослушиванием. Файлы `*.wav`/`*.pt`/`*.onnx` не коммитятся (`.gitignore`) — для
  прослушивания нужно перегенерировать локально по `ai/bench/README.md`.

**Наблюдение:** Piper (onnxruntime, fp32) на порядок быстрее Silero (torch) по RTF (~0.05
против ~0.06-0.21) и легче по памяти (~350 МБ против ~1.2 ГБ) — ожидаемо для
onnxruntime-инференса против PyTorch с полным рантаймом. Оба — быстрее реального времени
(RTF < 1) на этом CPU.

## 5. Что изменено в адаптерах, чтобы они реально заработали

- **`voice/tts/silero_provider.py`** — переписан. Старая версия звала `torch.hub.load(
  repo_or_dir="snakers4/silero-models", ...)`, что и качает веса при каждом создании
  объекта (нарушение раздела 11: «не скачивать модели при запуске»), и требует доступа к
  `github.com` вне scope этой сессии (раздел 1). Новая версия принимает путь к уже
  скачанному локальному файлу `.pt` (как и `PiperTTS`) и грузит его через
  `torch.package.PackageImporter(...).load_pickle("tts_models", "model")` — тот же формат,
  которым Silero реально распространяет `v4_ru.pt` на `models.silero.ai`. Также заменён
  несуществующий в реальном API параметр `apply_tts(..., rate=...)` (в `v4_ru` его нет) на
  SSML (`ssml_text=`) с тегами `prosody rate=/pitch=`, которые модель поддерживает
  (`model.valid_tags`) — это ближе к настоящей просодии, чем предполагавшийся `rate`.
- **`voice/tts/piper_provider.py`** — переписан под фактически проверенную версию пакета
  `piper-tts==1.8.0` (форк `OHF-Voice/piper1-gpl`). Старый код звал
  `voice.synthesize_stream_raw(text, length_scale=..., noise_scale=..., noise_w=...)` —
  этого метода нет в установленной версии; актуальный API —
  `voice.synthesize(text, syn_config=SynthesisConfig(...))`, возвращающий
  `Iterable[AudioChunk]` с `.audio_int16_bytes`; параметр переименован
  `noise_w` → `noise_w_scale`.
- **`voice/stt/vosk_provider.py`** — `VoskSTT.transcribe` раньше ожидал «сырой» PCM ровно
  на частоте конструктора (`sample_rate=16000` по умолчанию); `run_stt_bench.py` же читает
  `<utterance>.wav` **с** заголовком RIFF и передаёт эти же байты в оба STT-адаптера
  (`FasterWhisperSTT` их сам декодирует через `ffmpeg`/`av`, а `Vosk.AcceptWaveform` — нет).
  Добавлена `_pcm_and_rate()`: если во входных байтах есть заголовок `RIFF`/`WAVE`,
  адаптер сам вытаскивает PCM-кадры и фактическую частоту дискретизации из заголовка;
  иначе считает вход уже сырым PCM на частоте конструктора. Без этой правки Vosk либо
  падал на заголовке как на «аудио», либо (что хуже) молча выдавал мусорный WER на
  реальном несовпадении частоты — исправление не косметическое.
- **`ai/bench/run_stt_bench.py`** — добавлен разбор WER/CER по категориям сущностей
  (адрес/число/отрицание/служба), путь к модели Vosk сделан настраиваемым через
  `DDS_BENCH_MODELS_DIR` (было захардкожено `models/vosk-model-ru`, несуществующее имя),
  добавлены число ядер CPU и пиковая RSS в вывод.
- **`ai/bench/run_tts_bench.py`** — `_estimate_duration_s` раньше всегда считала
  длительность аудио по `sample_rate=22050`, что даёт неверный RTF для любого кандидата на
  другой частоте (Silero — 48000 Гц: RTF был бы занижен более чем вдвое). Теперь частота
  берётся из `provider.sample_rate`. Пути к моделям — через `DDS_BENCH_MODELS_DIR`.
  Добавлены время загрузки модели и пиковая RSS в вывод.
- **`ai/bench/synthesize_dataset_audio.py`** — `_register_known_candidates()` раньше
  вызывалась после построения `argparse`-парсера, поэтому `--tts-candidate` всегда получал
  пустой список допустимых значений (`choices=sorted(CANDIDATES)` считался до регистрации
  кандидатов) — воспроизводимая ошибка `invalid choice`, из-за которой сгенерировать
  тестовое аудио было невозможно даже с установленными весами. Регистрация перенесена
  перед построением парсера; частота записи WAV теперь берётся из `provider.sample_rate`
  по умолчанию (раньше — захардкожено 22050, что исказило бы Silero-аудио).
- Тесты на новую логику (без весов, без пакетов `piper`/`vosk`/`torch` — модули
  подменяются через `sys.modules`) — `ai/tests/test_voice_real_adapters.py`, 10 тестов:
  `_pcm_and_rate` (WAV-контейнер и сырой PCM), валидация голоса/интонации у обоих TTS,
  сборка SSML и int16-конвертация у Silero, передача параметров интонации у Piper.

## 6. Что не проверено и почему

- **GigaAM, T-one, XTTS-v2, F5-TTS** — не прогонялись. Раздел задания ограничивает
  ~20 минутами на кандидата; время контейнера потрачено на 3 STT- и 4 TTS-конфигурации
  (2 движка × 2 голоса), которые реально заработали и дали числа. GigaAM (NeMo-зависимости)
  и T-one (нативная зависимость KenLM) требуют более тяжёлой установки — не начаты, не
  недоступны по сети.
- **Другие голоса Piper на HF** (кроме `irina`/`denis`) и другие модели Vosk (кроме
  `vosk-model-small-ru-0.22`) — не проверялись; `irina` несёт лицензионный риск датасета
  (см. `docs/ai/licenses.md`) — для поставки нужно подобрать альтернативу.
- **Пиковая память — не изолирована от Python/интерпретатора и загрузки пакета.** Цифры —
  `ru_maxrss` всего процесса (`resource.getrusage`), включая сам интерпретатор Python,
  `numpy`/`torch`/`onnxruntime` при импорте и т.д., не только веса модели. Для честного
  сравнения именно веса-в-памяти нужен профайлер по факту (`tracemalloc` на уровне
  библиотеки или `/proc/<pid>/smaps` до/после), не сделан здесь.
- **Латентность STT — не потоковая.** `faster-whisper`/`vosk` в этих адаптерах принимают
  готовый буфер целиком (раздел 6.2 промпта требует частичные результаты по мере
  поступления) — задержка выше отражает время на распознавание всего буфера, не время до
  первого partial-результата. Внешняя VAD-нарезка для честной потоковой метрики не
  реализована (см. докстринг `faster_whisper_provider.py`).
- **Время до TTS — не до первого звука.** Как и в M2: `TTSProvider.synthesize()` не
  потоковый API, `avg_time_to_full_audio_s` — время до полного буфера, не до первого звука
  в потоковом смысле D-052/6.4 (другая величина, не путать).
- **WER/CER без нормализации чисел/падежей** (как и в M2): STT может выдать «12», эталон —
  «двенадцать» — считается ошибкой. Отдельный normalizer перед сравнением не реализован
  (`ai/bench/metrics.py`), цифры по числам в разделе 3 завышают реальную ошибку STT на
  числительных.
- **Аудио — синтетическое** (раздел 4): даже смешение голосов/движков не заменяет живую
  речь/телефонию (шум, эхо, перебивания, дефекты линии) — WER на реальных звонках будет
  выше, чем в этом отчёте, у всех кандидатов.
- **Лицензии голосов/весов** — только частично перепроверены по фактическим карточкам
  (см. `docs/ai/licenses.md`): `vosk-model-small-ru-0.22` (MIT, подтверждено),
  `piper/denis` (CC0 датасет), `piper/irina` (лицензия датасета не указана — риск),
  `silero v4_ru` (CC BY-NC-SA 4.0, подтверждено из `LICENSE`). `faster-whisper` — веса не
  перепроверены отдельно по карточке конкретного чекпойнта на HF (только по README/LICENSE
  репозитория кода).
- **Не целевой CPU** (раздел 9, D-051): 4 ядра вместо ≥6, без учёта конкурентности
  (≥20 одновременных сессий по ТЗ) — цифры этого отчёта не масштабируются линейно на
  конкурентную нагрузку и не заменяют замер на профиле `cpu`.

## 7. Как повторить

```bash
cd ai && source .venv/bin/activate
pip install -e ".[voice-fasterwhisper,voice-vosk,voice-piper,voice-silero]"

mkdir -p bench/models
# faster-whisper скачивает веса сам при первом обращении (huggingface.co)
# Vosk:
curl -L -o /tmp/vosk.zip https://alphacephei.com/vosk/models/vosk-model-small-ru-0.22.zip
unzip /tmp/vosk.zip -d bench/models/
# Piper (голоса):
for v in irina denis; do
  curl -L -o "bench/models/ru_RU-$v-medium.onnx" \
    "https://huggingface.co/rhasspy/piper-voices/resolve/main/ru/ru_RU/$v/medium/ru_RU-$v-medium.onnx"
  curl -L -o "bench/models/ru_RU-$v-medium.onnx.json" \
    "https://huggingface.co/rhasspy/piper-voices/resolve/main/ru/ru_RU/$v/medium/ru_RU-$v-medium.onnx.json"
done
# Silero (прямые веса, не torch.hub):
curl -L -o bench/models/v4_ru.pt https://models.silero.ai/models/tts/ru/v4_ru.pt

cd bench
python selfcheck.py
python synthesize_dataset_audio.py --tts-candidate piper-irina --out-dir /tmp/bench-audio
```
