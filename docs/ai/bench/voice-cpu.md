# Бенчмарк STT/TTS на CPU — M2

Дата: 28.09.2026. **Это не целевое железо заказчика** (раздел 9 промпта) — окружение сборки
агента, а не сервер профиля `cpu` (≥6 ядер, 32 ГБ RAM, D-051). Ни одна модель не утверждена
этим отчётом (раздел 11).

## Что измерено

**Ничего с реальными весами.** Сетевая политика этого контейнера блокирует все хосты, где
раздаются веса кандидатов из раздела 6.2/6.3 промпта:

| Хост | Нужен для | Результат проверки |
|---|---|---|
| `huggingface.co` | веса faster-whisper/Whisper, GigaAM, Piper-voices, XTTS, F5-TTS | `CONNECT` отклонён прокси, код 403 |
| `alphacephei.com` | модели Vosk | `CONNECT` отклонён прокси, код 403 |
| `models.silero.ai` | веса Silero TTS/torch.hub | `CONNECT` отклонён прокси, код 403 |
| `github.io` | GitHub Pages (демо-сэмплы Piper и т.п.) | `CONNECT` отклонён прокси, код 403 |
| `pypi.org`, `github.com`, `raw.githubusercontent.com` | pip-пакеты, исходный код, README/LICENSE | Доступны |

Проверено 28.09.2026 из окружения агента (`curl` через прокси; список сброшенных
соединений виден в `/root/.ccr/README.md` → `__agentproxy/status`). Установка pip-пакетов
(`faster-whisper` и т. п.) работает; загрузка их весов при первом обращении к модели падает
с той же 403-ошибкой прокси — воспроизведено на `FasterWhisperSTT("tiny")`.

Правило задания: «если окружение не пускает скачать пакеты/веса — не обходи ограничения,
опиши, что замер не выполнен и почему». Замер WER/CER/задержки/RTF на реальных моделях
**не выполнен** по этой причине, не по недосмотру.

## Что сделано вместо реального замера

1. **Обвязка бенчмарка** (`ai/bench/`) реализована полностью и работает: датасет из 10
   синтетических учебных реплик с адресами, номерами домов, числами, отрицаниями и
   названиями служб (`ai/bench/dataset.py`); WER/CER на расстоянии Левенштейна без внешних
   зависимостей (`ai/bench/metrics.py`); скрипты `run_stt_bench.py`/`run_tts_bench.py` с
   печатью хоста/CPU и явной пометкой «не целевое железо заказчика».
2. **Самопроверка на фейковых провайдерах** (`ai/bench/selfcheck.py`, `FakeSTTProvider`/
   `FakeTTSProvider` из `ai/src/dds_ai/voice/{stt,tts}/fake.py`) подтверждает, что цикл
   замера и метрики считают корректно: 10/10 реплик, WER=CER=0, что и ожидалось на
   зеркальном фейке. Это проверка машинерии, **не** качества какой-либо модели.
3. **Адаптеры реальных кандидатов** (`faster_whisper_provider.py`, `vosk_provider.py`,
   `piper_provider.py`, `silero_provider.py`) написаны по публичным API соответствующих
   библиотек и лениво импортируют тяжёлые зависимости (extras `ai[voice-...]` в
   `ai/pyproject.toml`), чтобы базовый пакет и тесты работали без них. `FasterWhisperSTT`
   проверен на **конструирование** объекта `WhisperModel` — пакет `faster-whisper`
   устанавливается через pypi.org и импортируется без ошибок; создание модели `tiny`
   доходит до попытки скачать веса и падает с сетевой 403-ошибкой прокси, что и
   задокументировано выше как граница проверки. Остальные три адаптера не запускались
   даже настолько далеко (зависимости `vosk`/`torch`/`piper-tts` не устанавливались, чтобы
   не тратить время контейнера на заведомо недостижимую загрузку весов).

   и/или `alphacephei.com` (Vosk) и/или `models.silero.ai` (Silero) — либо предзагрузка

## Известные методологические ограничения (даже после снятия сетевого блока)

- `run_tts_bench.py` меряет время до **полного** буфера синтеза (`TTSProvider.synthesize`
  не потоковый), не до первого звука в потоковом смысле — не путать с D-052/6.4 «первый
  звук ответа руководителя ≤3 с», это разные величины.
- Аудио, сгенерированное самим TTS, для замера STT — смещённый датасет (совпадение
  доменов завышает качество); честный замер STT требует живой или хотя бы стороннего
  происхождения речи, не собственного TTS-кандидата.
- WER/CER считаются посимвольно/пословно без нормализации чисел/падежей — сравнение
  гипотезы STT с эталонным текстом в этом виде переоценивает ошибки на числительных
  (STT может выдать «12», эталон — «двенадцать», или наоборот); для честной метрики по
  сущностям (адрес/число/служба) нужен отдельный normalizer перед сравнением — не
  реализован в `ai/bench/metrics.py`, это заготовка, а не финальная методика.
- `faster-whisper` не даёт нативных потоковых partial-результатов — нужна внешняя
  VAD-нарезка, не реализованная здесь (см. docstring `faster_whisper_provider.py`).
- Лицензии весов не проверены на страницах конкретных моделей (см.
  [`docs/ai/licenses.md`](../licenses.md)) — только на уровне репозитория кода.
