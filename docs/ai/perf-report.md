# Отчёт о производительности и наблюдаемости (раздел 9 промпта, D-051/D-052)

Свод существующих замеров: [`bench/voice-cpu.md`](bench/voice-cpu.md) (STT/TTS),
[`bench/llm-cpu.md`](bench/llm-cpu.md) (LLM-формулировка, семантический оцениватель),
[`calibration-report.md`](calibration-report.md) (качество оценивателя). Новых замеров этот
узел не проводил — только сведение уже полученных чисел в формат раздела 9 промпта и явный
список непроверенного.

Ни один из перечисленных замеров не сделан на целевом железе заказчика (D-051: CPU ≥6 ядер,
32 ГБ RAM) — везде указано окружение сборки агента (4 логических CPU, ~15 ГБ RAM). Ни один
замер не подтверждает продуктовые цели ТЗ (UI ≤2 с, ≥20 одновременных сессий, голос ≤150 мс) —
они относятся к транспорту/бэкенду, не к ИИ-контуру (см. «Что не проверено» ниже).

## 1. Раздельные стадии задержки (как требует раздел 9)

| Стадия | Измерено | Источник | Условия |
|---|---|---|---|
| Транспорт аудио | **нет** | — | вне ИИ-контура (медиатракт — бэкенд/клиент, 4.2) |
| Завершение STT | да, до финального результата (не потоково) | [`bench/voice-cpu.md`](bench/voice-cpu.md) §3 | `faster-whisper-medium` p50 7,75 с / `-small` 3,08 с / `vosk-small` 0,85 с на 1 реплике, синтетическое аудио, 4 ядра |
| Генерация LLM (реплика руководителя) | да, дымовой прогон на случайных весах (M3) и на настоящей модели вне схемы реплики (M5, свободная задача) | [`bench/llm-cpu.md`](bench/llm-cpu.md) §«Результаты»/«M5» | реплика руководителя на настоящей модели по своей схеме `{"action","text"}` — **не прогнана**; есть только близкая по духу свободная задача (медиана 4,95 с, p95 7,47 с, 24 вызова) |
| Первый звук TTS | **нет**, измерено только время до полного буфера | [`bench/voice-cpu.md`](bench/voice-cpu.md) §4 | `TTSProvider.synthesize()` не потоковый API — до полного буфера: Piper ~0,2 с, Silero 0,17–0,74 с |
| Оценка (семантический критерий) | да, на реальной модели, по одному вызову | [`bench/llm-cpu.md`](bench/llm-cpu.md) §«Прогон через LLMSemanticJudge» | Qwen2.5-1.5B Q4, 27 вызовов: медиана 5,1 с, p95 6,47 с, max 7,47 с — **сумма отдельных вызовов**, не время попытки целиком (попытка обычно требует 2–3 критерия подряд в полосе `max_concurrency: 1`) |
| Итоговая задержка до слышимого ответа | **нет** | — | требует STT + LLM + TTS вместе на настоящих весах; ни разу не прогнаны как одна цепочка |

## 2. Железо, модели, квантизация, конкурентность

| Параметр | Значение |
|---|---|
| CPU | `Intel(R) Xeon(R) Processor @ 2.80GHz`, 4 логических ядра, без GPU |
| RAM | ~15 ГБ (окружение сборки агента) |
| ОС | Linux 6.18.44 (glibc 2.39), контейнер |
| Python | 3.11.15 |
| STT-кандидаты | `faster-whisper` 1.2.1 (int8), `vosk` 0.3.45 (`vosk-model-small-ru-0.22`, без квантизации) |
| TTS-кандидаты | `piper-tts` 1.8.0 (`ru_RU-{irina,denis}-medium`, fp32, onnxruntime), Silero `v4_ru` (torch 2.14, fp32) |
| LLM/оцениватель | `Qwen2.5-1.5B-Instruct-GGUF` Q4_K_M (1,04 ГиБ), `llama-cpp-python` 0.3.35; дополнительно `Qwen2.5-3B-Instruct` Q4 на калибровке (не на задержке) |
| Конкурентность | 1 (последовательные вызовы; STT/TTS — по одному кандидату на процесс, LLM/оцениватель — один разговор за раз) |

Конкурентность >1 и профиль `gpu` — не замерялись ни разу (явно отмечено в обоих исходных отчётах).

## 3. Ошибки и деградация

Не входит в раздел 9 напрямую, но относится к наблюдаемости: журнал сбоев (компонент, время,
тип, затронутые доказательства) реализован и проверен тестами — [`c04-matrix.md`](c04-matrix.md),
`ai/src/dds_ai/faults.py`, `ai/src/dds_ai/worker/service.py::status()`. Статус компонентов для
администратора (`InferenceWorker.status()`) реализован и покрыт `test_worker.py`, но не
интегрирован с реальным UI администратора (вне ИИ-контура).

## 4. Явно непроверенное (раздел 9: «перечисли непроверенное явно»)

- **Целевой CPU заказчика (D-051: ≥6 ядер, 32 ГБ RAM).** Все числа этого отчёта — с
  окружения сборки агента (4 ядра, ~15 ГБ). Ни линейно, ни как-либо иначе они не
  экстраполированы на целевую машину.
- **≥20 одновременных сессий.** Не замерялось ни разу — ни на STT/TTS/LLM/оценивателе, ни на
  полном цикле. Раздел 9 прямо запрещает обещать конкурентную нагрузку без замера; здесь
  этого обещания нет.
- **Передача голоса ≤150 мс.** Это транспортная метрика медиатракта (бэкенд/клиент, 4.2),
  не ИИ-контура; замер не относится к этому пакету и не заявлен.
- **UI ≤2 с.** Вне ИИ-контура; не измерялось.
- **Итоговая задержка до слышимого ответа** (STT → LLM → TTS одной цепочкой на настоящих
  весах). Не прогонялась ни разу — есть только раздельные числа по стадиям (раздел 1 выше).
- **Первый звук TTS** (не полный буфер) — адаптеры не потоковые, число физически не
  измерено этим прогоном.
- **Потоковый STT** (частичные результаты по ходу речи, раздел 6.2 промпта) — адаптеры
  принимают готовый буфер целиком; задержка «завершения STT» в разделе 1 — не задержка до
  первого частичного результата.
- **Задержка полной попытки у семантического оценивателя** (несколько критериев подряд в
  фоновой полосе с `max_concurrency: 1`) — есть только оценка «может приблизиться к 15 с» по
  сумме отдельных вызовов, не измерение на реальном прогоне попытки.
- **Пиковая память по модели отдельно от интерпретатора** — числа RSS в `bench/voice-cpu.md`
  включают весь процесс Python (numpy/torch/onnxruntime при импорте), не только веса модели.
- **GigaAM, T-one, XTTS-v2, F5-TTS, 7B-модели** — не прогонялись вовсе (нехватка времени/
  зависимостей, см. `bench/voice-cpu.md` §6 и `bench/llm-cpu.md`).
- **Остановка inference видна администратору** — реализовано (`set_available`,
  `status()`), но не проверено сквозным сценарием «администратор видит остановку в UI»,
  поскольку UI администратора вне ИИ-контура.
