# ADR-0002. Голосовые адаптеры и обвязка бенчмарка (M2)

Дата: 28.09.2026. Статус: принято для M2; выбор конкретной модели STT/TTS — открыт
до замера на целевом железе (см. `docs/ai/bench/voice-cpu.md`).

## Контекст

- `ports.py` (M0) уже определяет `STTProvider`/`TTSProvider` с `model_ref`; менять
  контракт не требовалось.
- Сетевая политика окружения агента блокирует `huggingface.co`, `alphacephei.com`,
  `models.silero.ai` (403 через прокси), но пропускает `pypi.org`, `github.com`,
  `raw.githubusercontent.com` — можно ставить pip-пакеты и читать исходники/лицензии
  кандидатов, но не их веса.

## Решения

1. **Голосовой модуль — `ai/src/dds_ai/voice/`**, а не расширение `mocks/` или нового
   пакета: это владеет ИИ-контур напрямую (раздел 4.1 промпта, D-024/D-025), не мок
   соседнего модуля.
2. **Тяжёлые зависимости — опциональные extras** `voice-fasterwhisper`, `voice-vosk`,
   `voice-silero`, `voice-piper` в `ai/pyproject.toml`; адаптеры делают `import` внутри
   `__init__`/метода с понятным `ImportError`, чтобы `pip install -e "ai[dev]"` и тесты
   работали без единого мегабайта весов.
3. **Сигнал неуверенности по критическим сущностям — не новый контракт**, а
   dataclass `UncertainEntity` внутри `voice/confidence.py`: он не пересекает границу
   ИИ-worker ↔ бэкенд (не входит в `AttemptEvent`/`CriterionResult`), это внутренний
   сигнал «руководителю стоит переспросить». Если в M3/M4 понадобится передавать его как
   часть контракта диалога — регистрировать в `contracts/` и `SCHEMA_MODELS` тогда.
4. **Нормализация чисел для TTS — своя реализация**, не `num2words`: избежать лишней
   обязательной зависимости в базовом пакете ради простого детерминированного
   преобразования (0..999 999 999, кардинальные числительные, без падежей/порядковых —
   этого достаточно для адресов и счёта, большего 6.3 не требует).
5. **«Интонация» для Piper/Silero — приближение через темп/вариативность** (`length_scale`/
   `noise_scale` у Piper, темп у Silero), не нативный параметр просодии ни у одной из
   моделей. Это сознательный временный компромисс, а не решение о финальном UX голоса —
   риск описан в `docs/ai/licenses.md` и docstring соответствующих адаптеров.
6. **Бенчмарк — только на фейковых провайдерах в этом окружении** (`ai/bench/selfcheck.py`):
   реальный замер невозможен без сети до весов (раздел «Если нет сети» задания). Обвязка
   (датасет, метрики WER/CER, скрипты) готова к прогону, как только веса станут доступны.

## Последствия

- Выбор конкретной STT/TTS модели остаётся открытым (соответствует статусу D-024/D-025
  «временно утверждено до пилота» в реестре) — ничего в `voice/` не хардкодит один
  кандидат как обязательный; `VoicePipeline` принимает любой `STTProvider`/`TTSProvider`.
- Когда сеть до весов появится, следующий шаг — прогнать `ai/bench/run_stt_bench.py` и
  `run_tts_bench.py` по инструкции в `ai/bench/README.md` и заполнить таблицу в
  `docs/ai/bench/voice-cpu.md` реальными числами, затем обновить `docs/ai/licenses.md`
  ссылками на карточки моделей на huggingface.co/alphacephei.com.
