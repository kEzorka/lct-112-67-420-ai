# ADR-0001. Стек ИИ-контура

Дата: 28.09.2026. Статус: принято для M0–M1; транспорт — открыт до ответа B03.

## Контекст

- Всё локально, без интернета, CPU-first, GPU — заменяемый ускоритель (D-051, C-10).
- Кандидаты STT/TTS (`faster-whisper`, `whisper.cpp`, `GigaAM`, `Vosk`, `T-one`, `Silero`, `Piper`) и llama.cpp-совместимые LLM имеют зрелые обвязки прежде всего на Python.
- Бэкенд — Java 25 / Spring Boot 4.1.1 (`docs/backend/contract-notes.md`); в нём подключён gRPC-клиент, но не используется. Протокол бэкенд ↔ ИИ-воркер не выбран.
- Контракты должен читать бэкенд на другом языке.

## Решение

1. **Язык — Python 3.11+**, пакет `dds-ai` в `ai/`. Причина: все кандидаты моделей доступны из Python без обёрток; Java-бэкенд с ИИ-воркером общается только через контракт.
2. **Контракты — pydantic v2 → JSON Schema в `/contracts`.** Модели — единственный источник; схемы генерируются и сверяются в CI. JSON Schema читается из Java (например, генерацией классов), и из неё же можно получить `.proto`.
3. **Транспорт — не фиксируем.** Адаптер транспорта отделён от контрактов. По умолчанию для M1–M3 — локальный HTTP + WebSocket (проще отлаживать, потоковый канал для реплик и `ack.*`). Если B03 выберет gRPC — добавляется gRPC-адаптер с теми же сообщениями, ядро не меняется.
4. **LLM runtime — llama.cpp-совместимый** (GGUF, CPU), через `LLMProvider`. Конкретная модель не утверждена до замера (раздел 11 промпта).
5. **Инструменты — pytest, ruff; CI — GitHub Actions** (`.github/workflows/ai.yml` → `ai/scripts/check.sh`).
6. **Веса моделей не в git** (`.gitignore`: `models/`, `*.gguf`, `*.onnx`, `*.bin`); поставляются локальным пакетом.

## Последствия

- Любая модель подключается через порт в `ai/src/dds_ai/ports.py` и вызывается через `FaultInjector.call()` — так каждый сбой попадает в журнал и тестируется.
- Изменение контракта = изменение модели + перегенерация схем + повышение `CONTRACTS_VERSION`.
- При выборе gRPC понадобится генерация `.proto` из схем — задача M1/M2, не M0.
