# M2. Голос — 28.09.2026

Ветка `ai/m2-voice`. Формат — раздел 13 `docs/ai/agent-prompt.md`.

## 1. Что сделано

- **Голосовой модуль** `ai/src/dds_ai/voice/`:
  - `pipeline.py` — `VoicePipeline`: mute/hold-гейтинг перед STT, вызовы STT/TTS через
    существующий `FaultInjector` (M0), доставка подтверждения через `mocks/media.py`
    (C-05), события `ack.generated`/`ack.sent_to_media`/`ack.played_by_client`/
    `model_failure`/`text_delivered` из уже существующих контрактов `contracts/events.py`
    (новых контрактов не добавлено, `CONTRACTS_VERSION` не менялся).
  - `confidence.py` — `detect_uncertain_entities`: сигнал неуверенности по адресу, числам,
    службам; не изобретает confidence, если модель его не отдаёт (инвариант 5) — при
    отсутствии confidence решает по структурному признаку (например, адрес без номера
    дома).
  - `normalize.py` + `numerals.py` — нормализация текста перед TTS: адресные сокращения
    (`ул.`, `д.`, `кв.`, …), числа → слова (0..999 999 999, без внешних зависимостей),
    аббревиатуры служб → побуквенное произношение (`МЧС` → «эм-че-эс»).
  - `hints.py` — доменный словарь для STT (службы, типы происшествий, адресные элементы,
    числительные), передаётся в `transcribe(..., hints=...)`.
  - `stt/fake.py`, `tts/fake.py` — детерминированные провайдеры для тестов без весов.
  - `stt/faster_whisper_provider.py`, `stt/vosk_provider.py`,
    `tts/piper_provider.py`, `tts/silero_provider.py` — адаптеры реальных кандидатов,
    тяжёлые зависимости — опциональные extras `ai[voice-fasterwhisper|voice-vosk|voice-piper|voice-silero]`
    (`ai/pyproject.toml`). Не запускались с реальными весами (раздел 4 ниже).
- **Бенчмарк** `ai/bench/`: `dataset.py` (10 синтетических реплик: адреса, номера домов,
  числа, отрицания, службы), `metrics.py` (WER/CER без внешних зависимостей),
  `run_stt_bench.py`, `run_tts_bench.py`, `synthesize_dataset_audio.py`, `selfcheck.py`,
  `README.md`. Не подключён к `pytest` (`ai/scripts/check.sh` его не вызывает) — отдельные
  скрипты, как требует раздел 6.2/8 промпта.
- **Отчёты**: `docs/ai/bench/voice-cpu.md` (результат попытки замера и её граница),
  `docs/ai/licenses.md` (лицензии STT/TTS-кандидатов по коду и весам, риски).
- **ADR**: `docs/ai/adr/0002-voice-adapters.md`.
- Обновлены `ai/README.md` (структура: `voice/`, `bench/`) и `ai/scripts/check.sh`
  (добавлен `bench` в `ruff check`/`ruff format --check`).
- Тесты: `ai/tests/test_voice_pipeline.py`, `test_voice_confidence.py`,

## 3. Замеры

**Реальный замер STT/TTS на CPU не выполнен.** Сетевая политика этого контейнера
блокирует `huggingface.co`, `alphacephei.com`, `models.silero.ai` (403 через прокси) —
именно там раздаются веса всех кандидатов раздела 6.2/6.3 промпта; `pypi.org`/
`github.com`/`raw.githubusercontent.com` доступны. Полный протокол проверки, что именно
сделано вместо замера (обвязка бенчмарка + самопроверка на фейках + подтверждение, что
`faster-whisper` устанавливается и падает именно на загрузке весов, а не на импорте) — в
[`docs/ai/bench/voice-cpu.md`](../bench/voice-cpu.md). Задание прямо разрешает этот путь:
«если нет сети — не обходи ограничения, опиши, что не выполнено и почему».

## 4. Что не проверено и почему

- **WER/CER, задержка финального результата STT, время до звука TTS, RTF на реальных
  моделях** — нет сети до весов (п. 3). Обвязка готова, инструкция по прогону — в
  `ai/bench/README.md` и `docs/ai/bench/voice-cpu.md`.
- **Лицензии конкретных файлов весов** (карточки моделей на HF/alphacephei/Silero) — те
  же хосты заблокированы; в `docs/ai/licenses.md` зафиксирована лицензия кода/репозитория
  и явный риск там, где он известен из README без карточки весов (Silero CC BY-NC-SA,
  F5-TTS CC-BY-NC, XTTS-v2 CPML).
- **Нативная потоковая работа STT** (частичные результаты по мере поступления аудио) —
  `VoicePipeline.ingest_audio` рассчитан на один буфер за вызов, как и текущий
  `STTProvider.transcribe`; настоящая потоковая нарезка (VAD-чанки) — задача
  inference-worker (M1/M3, узел A), не переопределялась здесь.
- **Интеграция с настоящим ИИ-руководителем** (диалоговый автомат) — `speak_ack` принимает
  готовый текст реплики напрямую, не через `contracts/dialogue.SupervisorReply`: этот файл
  и M1 — зона узла A, не тронуты. `VoicePipeline` рассчитан на подключение к нему без
  изменения своего API (принимает `text`, `voice`, `intonation`).
- **Итоговый выбор модели** — не сделан и не должен быть сделан на этом этапе (раздел 11:
  «не объявлять модели STT/TTS утверждёнными до замера и проверки лицензий»); D-024/D-025
  остаются «временно утверждено до пилота».
- **Реальная потоковая метрика «время до первого звука TTS»** — `TTSProvider.synthesize`
  не потоковый API, поэтому даже при доступных весах замер даст время до полного буфера,
  не до первого звука в потоковом смысле D-025 (отмечено в `ai/bench/README.md`).

## 5. Решения, принятые по ходу

- ADR-0002 (`docs/ai/adr/0002-voice-adapters.md`): голосовой модуль как прямое владение
  ИИ-контура (не мок); тяжёлые зависимости — extras; сигнал неуверенности — внутренний
  dataclass, не новый версионируемый контракт (граница ИИ-worker↔бэкенд не расширена);
  своя реализация числительных без внешней зависимости; интонация Piper/Silero — временное
  приближение через темп/вариативность, не нативная просодия.
- Нормализация чисел ограничена кардинальными числительными без падежей/порядковых форм —
  достаточно для адресов и счёта пострадавших/служб (6.3), не для отчётов на естественном
  языке общего вида.
- Порог `LOW_CONFIDENCE_THRESHOLD = 0.6` в `confidence.py` — рабочее значение команды,
  не откалибровано (калибровка — задача M5, раздел 6.6/D-039); при появлении размеченных
  примеров эту константу нужно пересмотреть.

## 6. Риски и вопросы к команде

**Вопросы оркестратору:**

1. **Лицензионный риск Silero TTS (CC BY-NC-SA 4.0), XTTS-v2 (CPML), F5-TTS (CC-BY-NC).**
   Все три — вероятные кандидаты по качеству голоса, но некоммерческая оговорка весов
   требует решения заказчика/юриста, а не команды (см. `docs/ai/licenses.md`, раздел
   «Вывод для пилота»). Нужно решение: исключать их из замера совсем или замерять
   качество, но держать вне списка кандидатов на поставку?
2. **Доступ к весам моделей для реального замера.** Нужен либо временный доступ к
   `huggingface.co`/`alphacephei.com`/`models.silero.ai` из контура разработки, либо канал
   переноса файлов весов извне (offline-загрузка на другой машине → копирование). Без
   этого раздел 6.2/6.3 промпта («прогони 2–3 кандидата на целевом CPU») невыполним ни на
   одном последующем шаге, не только здесь.
3. **Piper vs `piper1-gpl`.** Исходный `rhasspy/piper` — MIT, но не развивается (README
   отправляет на `OHF-Voice/piper1-gpl`, который зависит от GPL-лицензированного
   `espeak-ng`). Если для поставки заказчику важно избежать GPL-обязательств — нужно
   решение, замерять ли актуальный `piper1-gpl` или держаться устаревшего MIT-форка.
4. **Порог `LOW_CONFIDENCE_THRESHOLD`** (0.6, `voice/confidence.py`) — рабочее значение
   без калибровки; при первой размеченной выборке (M5, D-039) стоит явно пересмотреть, а
   не оставлять как принятое решение.

**Следующая веха:** M3 — LLM-реплики (формулировка реплик руководителя внутри разрешённых
действий, валидатор выхода, защита от инструкций в реплике ученика) поверх готового
`VoicePipeline.speak_ack`/`ingest_audio` — эта веха, как и M1 (узел A), в объём этой ветки
не входила.
