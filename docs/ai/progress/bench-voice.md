# bench-voice (узел V) — 28.09.2026

Ветка `ai/bench-voice`. Формат — раздел 13 `docs/ai/agent-prompt.md`. Задача: выполнить
реальный замер STT/TTS на CPU (раздел 6.2/6.3), который узел B (M2) не смог выполнить из-за
сетевой блокировки, после того как в сетевую политику добавили `huggingface.co`,
`*.huggingface.co`, `*.hf.co`, `alphacephei.com`, `models.silero.ai`.

## 1. Что сделано

- Проверил доступ ко всем пяти хостам из задания — все реально отдали байты весов моделей
  (`docs/ai/bench/voice-cpu.md`, раздел 1). Единственное оставшееся сетевое ограничение —
  `github.com` для произвольных репозиториев (`torch.hub.load(repo_or_dir="snakers4/...")`)
  вне scope этой сессии — не связано с политикой моделей, обойдено легитимно (прямая
  загрузка `.pt` с `models.silero.ai`, не сторонний источник).
- Скачал и прогнал на CPU реальные веса: `faster-whisper` small/medium (int8), `Vosk`
  `vosk-model-small-ru-0.22`, `Piper` голоса `irina`/`denis` (`ru_RU-*-medium`), `Silero`
  `v4_ru` (спикеры `baya`/`aidar`). GigaAM/T-one/XTTS-v2/F5-TTS не прогонялись — за отведённое
  время (~20 мин/кандидат) не начаты, не заблокированы.
- Переписал 3 адаптера в `ai/src/dds_ai/voice/` так, чтобы они реально работали с
  фактическими API установленных пакетов (не тем, под который были изначально написаны
  вслепую без весов) — `silero_provider.py`, `piper_provider.py`, `vosk_provider.py`.
  Детали и причины — `docs/ai/bench/voice-cpu.md`, раздел 5.
- Исправил 3 бага в обвязке бенчмарка (`ai/bench/`), из-за которых замер физически не
  проходил бы даже с доступными весами: пустой список `--tts-candidate` в
  `synthesize_dataset_audio.py` (регистрация кандидатов после построения парсера),
  захардкоженная частота 22050 Гц в оценке RTF/длительности (ломает Silero на 48000 Гц),
  несуществующий путь к модели Vosk. Добавил разбивку WER/CER по сущностям
  (адрес/число/отрицание/служба), число ядер CPU и пиковую RSS в вывод обоих
  `run_*_bench.py`.
- Добавил тесты на новую логику адаптеров без весов и без установки `piper`/`vosk`/`torch`
  (`ai/tests/test_voice_real_adapters.py`, 10 тестов, подмена модулей через `sys.modules`).
- Обновил `docs/ai/bench/voice-cpu.md` (полностью, реальные числа) и `docs/ai/licenses.md`
  (подтверждённые лицензии по фактическим карточкам весов: Vosk MIT, Silero CC BY-NC-SA 4.0
  из `LICENSE`, Piper `denis`/`irina` по карточкам голосов на HF — `irina` несёт риск).

## 3. Замеры

Полная таблица условий (CPU: Intel Xeon 4 ядра, RAM 15 ГБ, Python 3.11.15, версии
пакетов), WER/CER/задержка/RTF/пиковая память по каждому кандидату и оба датасета
(одноголосый и смешанный по голосам/движкам) — `docs/ai/bench/voice-cpu.md`, разделы 2-4.
Коротко: `faster-whisper-medium` — лучший WER (0.10-0.28 в зависимости от датасета),
`vosk-small` — быстрее и легче на порядок, но WER 0.47-0.54; `Piper` — на порядок быстрее
и легче `Silero` по RTF/памяти, оба — быстрее реального времени (RTF < 1) на этом CPU.

## 4. Что не проверено и почему

Полный список с обоснованием — `docs/ai/bench/voice-cpu.md`, раздел 6. Коротко:
GigaAM/T-one/XTTS-v2/F5-TTS не прогонялись (бюджет времени); пиковая память не изолирована
от интерпретатора/импорта пакета; STT/TTS не потоковые (латентность — до полного
буфера/файла, не до первого partial/звука); WER/CER не нормализованы по числительным;
аудио синтетическое даже при смешении голосов/движков — не заменяет живую телефонию; не
все лицензии весов перепроверены по карточкам (только Vosk/Silero/Piper — не
faster-whisper); замер не на целевом CPU-профиле (4 ядра вместо ≥6, D-051) и без
конкурентности.

## 5. Решения, принятые по ходу

- Адаптер `SileroTTS` меняет контракт конструктора (`SileroTTS(model_path, speaker=...)`
  вместо `SileroTTS(speaker)` с runtime-загрузкой через `torch.hub`) — это внутренний класс
  голосового модуля, не контракт `/contracts`, `CONTRACTS_VERSION` не менялся. Причина —
  раздел 11 промпта прямо запрещает скачивание моделей при запуске, а `torch.hub.load`
  делал это при каждом создании объекта; новая версия принимает уже скачанный локальный
  файл, как и `PiperTTS`, единообразно.
  Дальнейшая интеграция с медиатрактом (M1/M3) должна передавать путь к весам явно, не
  вызывать `torch.hub` — это уже отражено в новом коде.
- Интонация Silero перенесена с несуществующего параметра `rate=` в `apply_tts` на
  SSML-разметку (`<prosody rate=... pitch=...>`), которую модель `v4_ru` реально
  поддерживает (`model.valid_tags`) — ближе к настоящей просодии (темп **и** тон), чем
  раньше предполагавшийся только темп.
- Вместо одного датасета аудио для STT (голос одного TTS-кандидата) сделал второй,
  смешанный по голосам и движкам (Piper irina/denis + Silero baya/aidar), как просило
  задание («смешай несколько голосов/движков, если можешь») — не отменяет смещение
  «синтетическое аудио как вход STT» (раздел 4 `voice-cpu.md`), но снижает эффект
  «один голос TTS = один голос STT».
- Не стал устанавливать GigaAM/T-one (тяжёлые нативные зависимости — NeMo, KenLM) при
  оставшемся бюджете времени — предпочёл довести до конца и перепроверить лицензии для уже
  установленных 3 STT + 2 TTS кандидатов, чем начать четвёртый и не успеть.

## 6. Риски и вопросы к команде

**Вопросы оркестратору:**

1. **Piper-голос `irina` (женский) использован для D-025, но его карточка на
   huggingface.co указывает лицензию датасета как "Unknown".** Для замера/демо хакатона
   решение пользователя это допускает (M2-1/M2-3), но для поставки нужен либо другой
   женский `ru_RU`-голос Piper с известной лицензией датасета (не проверен здесь — время),
   либо отдельное подтверждение происхождения датасета `irina` от правообладателя.
2. **GigaAM и T-one из раздела 6.2 промпта не прогонялись.** Оба выглядели благоприятно по
   лицензии в `docs/ai/licenses.md` (MIT/Apache 2.0 соответственно) ещё по M2, но не
   проверялись фактически ни разу — если нужен более полный охват 2-3 кандидатов именно из
   их числа (а не faster-whisper/Vosk), нужен отдельный проход с бюджетом времени под
   установку NeMo/KenLM.
3. **Профиль `cpu` (D-051, ≥6 ядер/32 ГБ) всё ещё недоступен для замера.** Все цифры этого
   отчёта — на 4-ядерном контейнере агента; относительный порядок кандидатов
   (`faster-whisper-medium` лучше по WER, `Piper` легче `Silero`) вероятно сохранится, но
   абсолютные задержки/RTF на целевом железе будут другими — нужен отдельный прогон перед
   пилотом.
4. **Порог допустимого WER/CER для приёмки конкретной модели не задан.** Этот отчёт даёт
   числа, но не решает, что «достаточно хорошо» для голосового тренажёра — нужно решение
   продукта/методиста, не команды инженеров.
