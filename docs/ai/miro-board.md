## 02 Сквозной pipeline

Публикация → назначение → уведомление → карточка → действие → маршрутизация → голос → серверная сдача → оценка.

- [Источник: новые материалы] Инструкция по карточке 112 · скриншоты UI · классификатор 1 281 комбинация / 90 полей · РТУ Т16Р VoIP
- [Вывод] Загрузка, нормализация, обезличивание и контроль качества
- [Рекомендация] Версии → чанкинг → метаданные → индекс → локальная БЗ / RAG
- [Человек] Параметры сценария и эталона: тип · локация · сложность · тема
- [ИИ] Черновик: сценарий + `initial_card` + вопросы + эталон
- [Человек] Проверка и корректировка → publish `scenario_version` + `reference_version`
- [Система] assignment группе / диспетчеру → `attempt_created` + immutable version snapshot
- [ТЗ] Комментарий → корректировка вопроса/ответа. [Рекомендация] Обратная связь → версии правил, промптов, эталонов и датасетов
- [Источник + Вывод] Rule engine. Вход: извлечённые признаки + адрес + состояние карточки + версия. Выход: тип K / ЕКП L / сценарий M / главная служба N / маршрутизация O:CL
- [Рекомендация] NLP / LLM. Вход: речь / SMS / описание. Выход: top-k типа, теги / слоты, пропуски и противоречия; низкая уверенность → уточнить
- [MVP runtime] ИИ-оператор 112 создаёт `initial_card` → `notification_shown` → диспетчер ДДС `card_opened` ≤30 с → ручные `card_revision` → ответить / отказаться / перенаправить → нормативная маршрутизация → звонок ИИ-руководителю → `played_audio_ack` → `submit_clicked` → серверная `submit_accepted` ≤180 с от `card_opened`
- [Система] Event log: порядок · тайминг · регламент · evidence. Timeout фиксируется как событие и не создаёт действие, звонок или сдачу
- [Rule engine] Нормативная маршрутизация по classifier/routing_rules version. Только active-правила дают auto-pass/fail; ambiguous/quarantined → эксперт
- [ML / NLP] Top-k · теги · слоты · пропуски · объяснение. Не назначает службы; `source_uncertainty ≠ learner_error`
- [Evidence evaluator] passed · failed · not_done · no_evidence · technical_error · not_applicable · not_checked; без обязательного evidence результат provisional
- [Отчёт] Наблюдаемые события + criterion results + версии + объяснение + рекомендации
- [Профиль] Обновляется только после `valid_score`; предварительные и технически нарушенные результаты не ухудшают профиль
- [Рекомендация] Объяснимое следующее задание; уже начатая попытка и её версии неизменны

## 03 Модули ИИ и интерфейсы

Вход → модуль → выход.

- [ТЗ] Генератор сценариев. Вход: параметры темы + утверждённые материалы. Выход: JSON сценария
- [Рекомендация] RAG / поиск. Вход: запрос + фильтры версии. Выход: фрагменты + ссылки на источники
- [ТЗ] Генератор структурированного эталона. Вход: сценарий. Выход: действия, ответы и критерии
- [Rule engine] Единственный нормативный контур маршрутизации. Вход: признаки + адрес + Card + `routing_rules_version`. `rule_status = active | ambiguous | quarantined`; только active участвует в auto-pass/fail, остальные → эксперт
- [ML / NLP / LLM] Только извлечение признаков и поддержка: top-k · теги · слоты · confidence · пропуски · объяснение. Не определяет финальную маршрутизацию; `source_uncertainty ≠ learner_error`
- [ТЗ] Проверка грамматики после ручных изменений и в отчёте
- [Рабочая рубрика до утверждения] Карточка 20% · решение/маршрутизация 25% · голос 25% · процесс/время 20% · ручной ввод 10% → `rubric_version`
- [Evidence-based evaluator] event_stream + evidence + active rules + ML hints + grammar → `criterion_status: passed | failed | not_done | no_evidence | technical_error | not_applicable | not_checked`; без evidence итог provisional
- [Объяснение] criterion result → наблюдаемое событие/evidence → правило и версия → понятное обоснование
- [Адаптация] Только `valid_score` обновляет профиль и объяснимую рекомендацию. Provisional/technical/not_checked исключаются из профиля и рейтинга
- [Локальный model gateway] offline · CPU-first · GPU как заменяемый ускоритель · кэш · очередь · fallback; сбой модели не является ошибкой ученика
- [AttemptVersionSnapshot] scenario · reference · card_schema · classifier · routing_rules · rubric · time_policy · model/template · difficulty_config; freeze at start + audit
- [Вывод] Все ИИ-модули идут через локальный gateway; синхронные операции отделены от фоновых

## 04 Роли и Human in the Loop

**Преподаватель.** Утверждает и публикует версии · назначает занятия и режим · наблюдает попытки · рассматривает спорные случаи · получает индивидуальные и групповые отчёты.
- [ТЗ] Проверяет и утверждает версии сценариев и эталонов
- [ТЗ] Корректирует сценарий или эталон и оставляет комментарий
- [ТЗ] Видит автоматическую и экспертную оценки, объяснение и основания
- [ТЗ] Получает инсайты группы и даёт рекомендации

**Контрольные точки утверждения человеком.**
- [ТЗ] Утверждение версии сценария
- [ТЗ] Утверждение версии эталона
- [Экспертная корректировка] `score_version N+1 {parent, author, reason, timestamp}`; предыдущая версия неизменна и доступна в аудите

**Диспетчер ДДС (обучаемый).**
- [Q&A 16.09] Получает уведомление и готовую карточку от ИИ-оператора 112
- [Режимы] «делай как я» / самостоятельный. Ручное дополнение свободным текстом без типовых фраз → `card_revision` → ответить / отказаться / перенаправить → доклад ИИ-руководителю
- [ТЗ] Получает оценку, ошибки, объяснение и рекомендации

**Администратор.**
- users · roles · settings · health · персональные учётные записи · RBAC; сервисные операции аудируются; учебные оценки не изменяет
- [Инфраструктура] Производительность и локальный inference. 2FA/MFA, сеть, интеграции, GPU и облачный режим — вопрос заказчику
- [ТЗ] Мониторинг, безопасность и оповещение об ошибках
- [ТЗ] Резервное копирование не реже раза в сутки и аудит
- [Граница ответственности] Администратор не изменяет оценки или сценарии активной попытки; преподавательская корректировка — только новой ScoreVersion с аудитом

## 05 Данные и подготовка

Источник → обработка → хранилище → Card / TrainingAttempt / AttemptVersionSnapshot / ScoreVersion → доступ → версия → retention.

- [Вывод] Импорт → валидация → очистка / обезличивание → нормализация → версии → чанкинг / метаданные → индекс

**Источники.**
- [Источник] Инструкция по карточке 112: звонок / SMS, 4 блока, опросные карты, адрес / карта, службы, offline-синхронизация, блокировка, аудит
- [Источник] Классификатор: 1 281 правило · 24 группы · 90 столбцов · 51 ведомственный блок / 76 столбцов маршрутизации
- [Кандидаты] 96 билетов требуют экспертной валидации и provenance; до approval не являются нормативным эталоном и основанием auto-fail
- [ТЗ] Иные документы и учебно-методические материалы
- [ТЗ условно] Обезличенная выгрузка БД — при наличии у заказчика
- [ТЗ условно] Статистика обработки вызовов — при наличии выгрузки
- [ТЗ условно] Журналы действий — при наличии выгрузки
- [Вывод] MP3 / WAV: формат задан, но набор учебного аудио не подтверждён

**Хранилища и доменная модель.** PostgreSQL: `Card {source_payload, dispatcher_edits, card_revision[]}` · `TrainingAttempt {events, evidence, status}` · immutable `AttemptVersionSnapshot` · append-only `ScoreVersion`; object store: документы/аудио; vector index: RAG.

**Производные наборы.**
- [Рекомендация] Версионируемая база знаний: фрагменты, метаданные, источники
- [ТЗ + Вывод] Библиотека утверждённых сценариев
- [ТЗ + Вывод] Версионированные эталонные действия и ответы
- [Eval-набор] active-правила отдельно; 148 ambiguous и quarantined маршрутов → эксперт, не обычный auto-fail; low confidence → уточнение
- [Append-only ScoreVersion] attempt_id · parent_score_version_id · author · reason · timestamp · criterion_results[] · total_score · provisional; override создаёт N+1
- [TrainingAttempt events] notification_shown · card_opened · card_revision · selected_action · played_audio_ack · submit_clicked · submit_accepted · timeout
- [Доступ и версии] RBAC; AttemptVersionSnapshot 1:1 freeze at start; security logs ≥6 мес; retention остальных категорий — Q06 заказчику

**Форматы.** JSON сценариев и API · XML конфигураций · SQL / PostgreSQL · CSV отчётов · PDF / DOCX материалов · MP3 / WAV аудио.

- [Риск данных] Классификатор: 34 без ЕКП · 21 пустой сценарий + 9 «без сценария» · 102 без главной службы · 148 неоднозначных строк · 842 комментария. Импортировать значения + комментарии; версию утверждает владелец. Реальные выгрузки не гарантированы.

## 06 Ограничения, качество, безопасность

Обязательные НФТ: local/offline · CPU-first · GPU — заменяемый ускоритель.

- [PRIMARY] Локальный/offline учебный контур · без внешних AI API · реальные экстренные вызовы и сети не используются
- [PUBLIC DEMO] Отдельная trust zone · synthetic data only · нет связей с учебной БД, реальными аккаунтами и экстренными сетями
- [Runtime] CPU-first · квантизованная модель · кэш · очередь · мониторинг · deterministic fallback. Сбой рекомендательной модели не ухудшает профиль; начатое задание неизменно
- [Security baseline] Персональные учётные записи · RBAC · TLS внутри контура · защита от НСД. 2FA/MFA — Q07 заказчику
- [Audit / backup / deletion] Неизменяемый аудит действий и admin-операций · backup ≥1/сутки · deletion ledger/tombstone · после restore: purge replay → verify
- [Retention] Security logs ≥6 месяцев; сроки карточек, аудио, транскриптов, оценок и backup — Q06 заказчику
- [Базовый сервер] CPU ≥6 ядер · RAM ≥32 ГБ · NVMe ≥512 ГБ · GPU необязателен и уточняется в Q07
- [ТЗ] Не менее 20 одновременных сессий; интерфейс — до 100 пользователей
- [ТЗ] Отклик интерфейса ≤2 с при нагрузке до 100 пользователей
- [ТЗ] Аналитический отчёт ≤30 с
- [MVP] VoIP-эмулятор учебного звонка · end-to-end latency ≤150 мс · промышленная SIP/РТУ/Avaya не является зависимостью MVP · формальное признание эмулятора — Q04
- [Рейтинг admission rule] Только сопоставимые завершённые попытки: одинаковые scenario · difficulty · rubric · time_policy · help_policy; provisional/technical/not_checked исключаются
- [ТЗ] Защита персональных данных и обезличивание доступных выгрузок
- [Coverage классификатора] Измеряется по авторитетной версии Q02; целевой порог не утверждён; ambiguous/quarantined отдельно
- [Версионирование] AttemptVersionSnapshot фиксирует модель/шаблон, правила, классификатор, сценарий, эталон, рубрику, time policy и difficulty config

Метрики — кандидаты в протокол приёмки; официальные пороги, веса, critical errors и временные точки задаёт заказчик в Q05. Рекомендации к согласованию:
- доля сценариев, одобренных преподавателем;
- объяснение: ошибка, балл, основание и источник;
- воспроизводимость; устойчивость к неполным, разговорным и перефразированным ответам;
- частота галлюцинаций;
- задержка генерации / проверки и качество без GPU.

## 07 MVP и открытые вопросы

**MVP.**
- [Рекомендация MVP] Локальная база знаний / RAG — в ТЗ RAG прямо не назван
- [ТЗ MVP] Генерация сценария и структурированного эталона с утверждением преподавателем
- [Вывод MVP] Rule engine и NLP раздельно → гибридная агрегация
- [ТЗ + Вывод MVP] Отчёт с ошибками, временем и грамматикой; объяснение и рекомендации
- [MVP] Голосовой контур: VoIP-эмулятор → STT → ИИ-руководитель → TTS → `played_audio_ack`
- [MVP] Локальные STT/TTS · мужской и женский голоса · разные интонации · retry / deterministic fallback / текстовый разбор / not_checked; готовый голосовой датасет не предполагается
- [MVP] Адаптация выбирает следующее задание только после `valid_score`; активная попытка и её версии неизменны
- [MVP guardrail] Учебный VoIP не подключается к реальным экстренным сетям
- [Рейтинг] Только сопоставимые valid results; технические и preliminary результаты исключены
- [Human in the loop] Преподаватель утверждает сценарии/эталоны и создаёт ScoreVersion N+1 при экспертной корректировке; история не перезаписывается

**После MVP.** Прогнозная аналитика — отдельная продуктовая гипотеза, требует датасета · расширенные тепловые карты.
