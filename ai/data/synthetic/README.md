# Синтетические сценарии (M1 + M4b)

**Все файлы здесь — синтетика**, придуманная командой. Это не реальные билеты заказчика
(D-050) и не их производные: у них `provenance: "synthetic"`, пустой `source_ref`, заголовок
начинается с «СИНТЕТИКА». Город «Учебный» и все улицы/набережные вымышлены. Состав полей
карточки D-011 и нормативная маршрутизация здесь не утверждены: службы назначает мок движка
правил (`mocks/routing.py`), а не сценарий.

Набор расширен на M4b (6.5) до 9 сценариев для трёх условных профилей ДДС и покрывает три
решения диспетчера, типичные состояния связи и один диагностический сценарий (C-03). Матрица
покрытия — [`docs/ai/coverage-matrix.md`](../../../docs/ai/coverage-matrix.md).

| Файл | Профиль ДДС | Решение ДДС | Состояние вызова |
|---|---|---|---|
| `syn-001-fire-respond.json` | `dds-center` | ответить (`respond`) | соединение сразу; канал оператора 112 выключен (D-030) |
| `syn-002-gas-redirect.json` | `dds-center` | перенаправить (`redirect`) | «занято», затем «не отвечает», затем соединение |
| `syn-003-repeat-refuse.json` | `dds-center` | отказаться (`refuse`) | обрыв первого соединения после 2-й реплики |
| `syn-004-flood-respond.json` | `dds-river` | ответить (`respond`) | соединение сразу; известный факт «этаж» допускает пропуск (`omissible`) |
| `syn-005-transport-redirect.json` | `dds-north` | перенаправить (`redirect`) | «не отвечает», затем соединение |
| `syn-006-unclassified-diagnostic.json` | `dds-north` | отказаться (`refuse`) | диагностический (`diagnostic: true`, C-03): маршрут неподтверждён, `routing.services` неприменим |
| `syn-007-fire-respond-north.json` | `dds-north` | ответить (`respond`) | соединение сразу; описание несёт вариант формулировки (`variant_values`) |
| `syn-008-flood-refuse-river.json` | `dds-river` | отказаться (`refuse`) | обрыв первого соединения после 2-й реплики |
| `syn-009-gas-redirect-river.json` | `dds-river` | перенаправить (`redirect`) | «занято», затем соединение |

Схема — `contracts/scenario.schema.json`. `syn-003` и `syn-008` исключают `routing.services` из
применимых критериев не из-за неподтверждённого маршрута, а потому что ожидаемое решение —
«отказать»: служба не вызывается в принципе, это не относится к gate C-03 (см.
`ai/src/dds_ai/scenarios/lifecycle.py::check_publish_gate`). Единственный по-настоящему
диагностический сценарий — `syn-006`.
